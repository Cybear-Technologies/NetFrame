# Input group

Attach a prefix, suffix, or action to existing Input, Select, and Button components. No library JavaScript, implicit group semantics, or shared disabled state.

## Search with decorative prefix

Label the real input. Hide decorative icons or prefixes from assistive technology. A compact Go action leaves room for the search value on a narrow phone; its accessible name is Go: search records. This GET form submits to the same docs page and shows the query in the URL; no search service is provided.

## Multiple controls and select

Give **every** control its own label. This stacked example preserves the native select picker and arrow. Submit and reset use normal browser behavior. Inputs, single-row selects, addons, and buttons must be direct children of the group; listbox selects (`multiple`/`size`), wrappers, textarea, nested groups, and arbitrary child elements are not supported.

## Narrow layout strategy

Default `.nf-input-group` is one attached row. Use a bordered button variant such as `.nf-button-primary` or `.nf-button-ghost`; bare `.nf-button` intentionally retains its transparent border. Controls shrink; each addon or action is bounded to 40% and its text wraps. Use short option labels in a horizontal native select: browsers do not wrap selected option text.

Use **`.nf-input-group-stacked` explicitly** for long prefixes, long actions, several controls, or a narrow parent. It stacks every direct child to full width. Horizontal siblings share one overlapped border; stacked siblings share one overlapped horizontal border. No automatic viewport breakpoint is implied: the parent may be narrow even on desktop. There is no clipping or hidden-overflow workaround.

Each focusable child keeps its own raised focus ring. Validation belongs to the affected control, not the whole group. A disabled input does not disable its adjacent action; the Reset below deliberately remains available.

## Native state ownership

Readonly text controls remain focusable and submitted, but cannot be edited. Disabled controls are omitted from submission and native keyboard navigation. Prefer native `disabled`; `aria-disabled` supplies styling and semantics only, so consumers must prevent activation/editing if they use it instead.

`aria-invalid` does not perform validation or block submission. Provide linked error text and your application validation. Required fields still use native constraint validation. The static endpoint error above is illustrative, not a URL-validation engine. Use [Alert's error summary](/components/alert/#form-error-summary) for navigation to invalid controls.

## Compatibility

Same browser floor as NetFrame: Chrome/Edge 111+, Firefox 113+, Safari 16.2+. Selects deliberately keep their native arrow rather than a hard-coded green SVG. Native pickers and option truncation remain platform-owned; use stacked markup and suitable labels rather than promising arbitrary strings fit one row. No new runtime dependencies or exports.

## Class reference

| Class | Description |
|---|---|
| `nf-input-group` | Joined row of direct input, select, addon, or button children |
| `nf-input-group-addon` | Bounded, wrapping prefix or suffix; associate meaningful content |
| `nf-input-group-stacked` | Explicit full-width vertical composition with shared borders |
